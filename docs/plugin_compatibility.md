# Loon 插件兼容性深度审计与互操作指南

本文档全面梳理与本分流规则集（`.lsr`）协同运行的常用 Loon 插件生态，明确插件运行原理、规则优先级以及互操作注意事项。

---

## 1. 核心原则与法律声明

1. **零分发与零搬运**：
   - 外部插件官方源：
     * **iRingo 系列**：[https://nsringo.github.io/](https://nsringo.github.io/)
     * **Kelee Hub 系列**：[https://hub.kelee.one/](https://hub.kelee.one/)
   - 本仓库**严禁复制、修改或公开再分发**任何第三方插件代码及脚本内容。
2. **职责边界分离**：
   - **分流规则（本仓库）**：仅负责“流量归属判定”（识别请求属于哪个业务服务，如 Gemini、YouTube、Google Drive、Apple 服务等）。
   - **功能与去广告插件**：独立负责本地 Mock、URL Rewrite、Header 修改、Script 脚本篡改及专用 `REJECT` 拦截。
   - **禁止合并去广告规则**：主流去广告插件依靠内部的动态规则与 MitM 脚本自闭环，本仓库绝不盲目堆砌或合并广告拦截规则，保持规则库纯净精简。

---

## 2. Loon 核心优先级与拦截机制定律

在 Loon 的数据转发流水线中，规则严格遵循以下不可逆的优先级次序：

```text
┌──────────────────────────────────────────────────────────────┐
│ 1. 本地规则 [Rule] (最高优先级，优先无条件命中)             │
├──────────────────────────────────────────────────────────────┤
│ 2. 插件规则 [Plugin] 内部内置的 [Rule] (次高优先级)         │
├──────────────────────────────────────────────────────────────┤
│ 3. 远程订阅规则 [Remote Rule] (即本仓库的 dist/*.lsr 规则集) │
├──────────────────────────────────────────────────────────────┤
│ 4. 兜底策略 FINAL (未匹配时的默认落脚点)                     │
└──────────────────────────────────────────────────────────────┘
```

> [!IMPORTANT]
> **关键架构事实**：
> 远程分流规则（`.lsr`）位于第 3 层，**其优先级天然低于插件内置规则**。
> - 如果去广告插件将某个域名置为 `REJECT`，即使该域名出现在 `AI-Overseas.lsr` 或 `Google.lsr` 中，Loon 也会由于插件优先级更高而直接执行拦截。
> - 任何需要“绝对优先穿透”的个人例外，必须配置在本地 `.lcf` 的 `[Rule]` 顶层。

## 3. 重点高频插件兼容性深度核验

### A. DNS 防泄漏与 HTTPDNS 拦截类
* **代表插件**：`Prevent_DNS_Leaks`, `Block_HTTPDNS`
* **交互机制**：
  - `Block_HTTPDNS` 拦截腾讯、阿里、百度等大厂的 HTTPDNS 接口（如 `119.29.29.29`, `203.107.1.1` 或 `httpdns.alicdn.com`）。
  - 该行为强制 App 回退到操作系统本地 Local DNS 解析，由 Loon TUN 全权接管。
* **兼容性判定**：
  - **完全兼容**。本仓库 `China-Direct.lsr` 放行日常国内 App 域名，DNS 解析由 Loon 本地配置的 DNS 模块处理，不会与 HTTPDNS 拦截产生冲突。

### B. 管理与脚本转换工具类
* **代表插件**：`BoxJs`, `Sub-Store`, `Script-Hub`
* **交互机制**：
  - 通常在本地回环地址（`127.0.0.1` / `boxjs.net` / `sub.store`）通过本地 HTTP Server 与 HTTP-Request/Script 运行，涉及 MitM 泛域名证书重定向。
* **兼容性判定**：
  - **完全兼容**。本地局域网私网段（`127.0.0.0/8`）已在 `China-Direct.lsr` 明确声明直连，且此类管理工具依托本地 MitM 脚本拦截，不会被远程分流规则错误带跑。

### C. Apple 生态增强类
* **代表插件**：`iRingo.WeatherKit`
* **交互机制**：
  - 针对国内版 iPhone 无法完整显示部分天气数据（如降水强度、空气质量图层），通过 Rewrite/MitM 接入 Apple 原生 WeatherKit API（`weather-data.apple.com`）。
* **兼容性判定**：
  - **完全兼容**。该流量属于 Apple 基础直连服务范畴，位于 `Apple-Direct.lsr` 中。插件通过 MitM 修改响应体实现增强，分流规则保持直连即可，不会造成阻断。

### D. 废弃插件清理声明
* **`iRingo.Siri`**：
  - 随着 iOS 系统架构迭代及服务器侧端点更替，Siri 换区插件已基本失效。
  - **处置原则**：将在最终 `.lcf` 中完全移除该插件，**本规则仓库无需、也不应为已失效的 Siri 插件引入任何冗余的特殊分流规则**。

### E. 字幕、翻译与节点检测工具类
* **代表插件**：YouTube 双语字幕、节点测速与 IP 信息面板
* **交互机制**：
  - 依赖公开 API（如 `ipinfo.io`, `api.myip.la`, `ip-api.com`）。
* **兼容性判定**：
  - **完全兼容**。测速与面板插件各自直接发起 HTTP 请求，本仓库不对此类临时检测 API 进行过度代理绑定，交由用户全局或兜底策略处理。

## 4. 故障排查建议

当用户在使用某 App 遇到网络异常时：
1. **优先使用一键诊断插件**：运行 `LoonRules-Diagnostic.lpx`，排查是否属于节点失效或规则未命中；
2. **比对插件排除法**：若诊断显示节点与分流均正常，可临时在 Loon【插件】列表中关闭对应 App 的去广告插件，核验是否属于插件内部脚本误杀；
3. **日志脱敏核验**：使用 `python scripts/sanitize_log.py` 导出脱敏记录，快速定位被阻断的真实 Host。
